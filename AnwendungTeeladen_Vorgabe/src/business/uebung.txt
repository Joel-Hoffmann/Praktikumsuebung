clean Code
→ Regeln für gut lesbaren, wartbaren Code

1OSP
→ Methode macht entweder
→ Logik oder Integration (UI, Fehler Ausgabe)
→ nie beides
DRY – Don’t Repeat Yourself
→ gleicher Code darf nicht mehrfach existieren
→ zwei Methoden, zwei Mal Buffered Reader…
Chain Constructor
→ ein Konstruktor erledigt die Arbeit, die anderen delegieren
→ this(v, n, null)
→ damit kein Code doppelt

SOLID
→ Regeln für gutes objektorientiertes Design
Single Responsibility (SRP)
→ eine Klasse sollte nur einen Grund haben, geändert zu werden
Open Closed Principle
→ Code soll erweiterbar sein ohne ihn zu ändern, z. B. mit Vererbung / Polymorphie
Liskov Substitution Principle
→ Unterklasse muss überall dort einsetzbar sein,
wo die Oberklasse erwartet wird (Schraubendreher, Schleifgerät)
Interface Segregation Principle
→ Interfaces sollen klein sein
→ eine Klasse soll nur Methoden implementieren müssen,
die sie wirklich braucht
Dependency Inversion Principle
→ „High Level Code“ arbeitet eher mit Interfaces
als mit konkreten Klassen
